## What the product is

Pen is an MIT, offline-first desktop editor in Rust on Rune (GPU SDF, no
webview). macOS, Windows, Linux, all desktop architectures. Look is Ink and
Paper only: monochrome, 48pt notebook margin, hairline rules, no frosted
glass, no drop shadows, no colored status dots, no green/red diffs.

Network rule the user set, after waiving "fully offline": Pen never phones
home and never makes a background network call. Fetch, push, and merge connect
only when the user invokes them, through the system `git` binary. Open, edit,
save, find, status, diff, commit, and checkout stay local. There is no `pull`
command. `pull` is not on the allow-list.

Zed (`github.com/zed-industries/zed`) is the ergonomic reference for the git
dock: branch header, inline commit, per-file stage/discard, diff with `j`/`k`.
It is not a visual reference. Pen stays Ink and Paper.

## How you test it

From the repo root. First launch of `just run` compiles a release binary; that
takes a while. Later launches are the binary.

### Automated, before you trust a change

```sh
just gate
```

That is format check, `clippy --all-targets -- -D warnings`, every test, and
the two release budgets (10 MB open under 100 ms, keystroke plus viewport plus
highlight under 2 ms). A warning is a failure.

Headless frames, no window:

```sh
just scene diff-paper --snap /tmp/pen-diff-paper.png --size 1120x720 --scale 2
just scene diff-ink   --snap /tmp/pen-diff-ink.png   --size 1120x720 --scale 2
just scene git-ink    --snap /tmp/pen-git-ink.png    --size 1120x720 --scale 2
just scene git-paper  --snap /tmp/pen-git-paper.png  --size 1120x720 --scale 2
```

Other scene names: `empty-paper`, `empty-ink`, `editor-paper`, `editor-ink`,
`palette-ink`, `palette-paper`, `find-paper`. List them with
`cargo run -p pen -- --list-scenes`.

### By hand, in this order

Open a real git repo, not a subdirectory of one, for the first pass.
`just run /Users/aj/Developer/Projects/pen` is a fair target.

1. Empty window. The only control is "Open a folder". Sidebar toggle is hidden.
2. Open a folder. Sidebar appears. Files tab lists the tree. Ignored files and
   `.git` are absent.
3. Open a Rust file. Text is IBM Plex Mono. Line numbers sit after a wide left
   margin. Type, undo (`⌘Z`), redo (`⇧⌘Z`). Save (`⌘S`). The toolbar drops
   "edited".
4. `⌘F`. One line above the page, not a dialog. Enter finds the next hit.
   Escape closes it.
5. `⌘K`. Palette is instant, no animation. "Use Ink" and "Use Paper" switch
   the whole window. Custom theme, if you want one, is `theme.json` in the
   app config dir (`~/Library/Application Support/pen/` on macOS). A color
   under 4.5:1 against the ground is dropped.
6. Edit a file in another program. If your buffer is clean, Pen reloads it.
   If your buffer is dirty, the status line says "Changed on disk. Your copy
   is kept." and your text stays.
7. Git tab, only when the folder is inside a repo. You should see the branch
   name, Fetch, Push, Changes, Branches, Worktrees, History. No colored dot.
   A modified tracked file reads `+n −n` with a real minus sign. A new file
   reads `new`.
8. Click a change. The page becomes a diff titled "Changes — …". Added and
   removed lines are two shades of the same ink, not green and red. "Split
   diff" toggles layout with no animation. `j`/`k` and `]`/`[` move in the
   diff when it has focus.
9. Click `+` on a change, then Commit. One line, like Find. Enter commits.
   A blank message is refused. If `user.name` or `user.email` is missing, the
   status line says to set them and your typed message is still there.
10. Make a dirty edit and do not save. Try checkout, discard, merge, or
    removing a worktree. Status line keeps your copy. Nothing on disk changes.
    Save or revert, then discard asks "Discard changes to {name}?" Decline
    leaves the file. Confirm restores the index copy.
11. Add worktree: `+` beside Worktrees, two lines (path, branch), not a wizard.
    Remove asks "Remove worktree {path}?" and only then deletes. The worktree
    you have open has no remove button.
12. Fetch and Push need a remote and a credential helper already set up. Pen
    will not pop a password prompt (`GIT_TERMINAL_PROMPT=0`). A missing `git`
    binary says "Git is not installed." Status and diff still work. A hung
    remote must not freeze Save.

If step 7 is missing, the folder is not inside a git repo, or the snapshot
has not arrived yet (it refreshes at most every 200 ms, off the UI thread).

## What Phase 1 actually contains

Commits `7a424d1` through `78cadb8`. Crates: `buffer`, `project`, `highlight`,
`app` (package `pen`).

- Rope buffer, undo cap 256, viewport slice (visible lines plus overscan),
  literal find, IME preedit that does not enter undo.
- Editor page drawn by Rune. Only the viewport is shaped.
- Project walk honors `.gitignore`, skips `.git`, drops symlinks that leave
  the root. Reads are UTF-8 or "not UTF-8", never a lossy decode. Writes are
  atomic (`.pen-tmp` then rename).
- Disk watcher, 50 ms debounce. Dirty buffer wins over the file on disk.
- Ink and Paper. `highlight::load_theme` is the only theme parser. Contrast
  floor is 4.5:1. Syntax is a five-step OKLab ramp of `fg` toward `bg`.
- Chrome: 248 pt sidebar (160–480), toolbar, command palette (`⌘K`), Find
  (`⌘F`). Palette and Find open with zero animation.

Measured at the Phase 1 gate, release, 10 MB / 161,321 lines: open 7.82 ms,
keystroke plus viewport plus highlight 111 µs. Later release runs were in the
same band (about 15 ms open, about 226 µs keystroke). Budgets are 100 ms and
2 ms.

## What Phase 2 actually contains

Commits `99c941e` through `71464f9`. New crate `crates/git`, package `pen-git`.

The UI thread never calls `gix` and never spawns `git`. A Tokio worker on the
`pen-io` thread publishes `GitSnapshot` on a `watch` channel, at most every
200 ms, and on save. Opening a project and a disk-watch event also trigger it.

| Surface | Where | Behavior |
| :--- | :--- | :--- |
| Status label | file tree and Changes | `+n −n` or `new` or nothing. Faint token. No dot. |
| History | Git dock | Newest first, summary plus 7 hex chars, cap 50. |
| Diff | main page | Unified patch from `gix`, drawn by `rune_kit::DiffView`. |
| Stage | `+` on a row, or "Stage file" | Index update. Does not touch the editor buffer. |
| Commit | palette or Git flow | Single line. Author from repo git config. |
| Branches | Git dock and "Checkout {name}" | Local branches only. |
| Discard | `↺`, then confirm | Restores the index blob, or deletes an untracked file. |
| Worktrees | Git dock | List, add (path + branch), remove after confirm. |
| Fetch, Push, Merge | header buttons and palette | System `git` only. Allow-list is those three words. |

Commands in the palette now: Open folder, Save, Find, Stage file, Discard
file, Commit, Fetch, Push, Merge, Add worktree, Split diff, Use Ink, Use
Paper, plus "Checkout {branch}" and "Merge {branch}" for each local branch.

There is no force-push, no hard reset, no rebase, no unstage, no partial
hunk stage, no branch create/delete UI, no remote-branch checkout, no pull.
Do not add them in a drive-by.

## Rulings already made

A later agent that "fixes" these without a new human decision is redoing
settled work.

- `Theme` has `added` and `removed`. They are OKLab ink steps, overridable in
  `theme.json`, dropped under 4.5:1. `rune_kit` success/danger colors are
  mapped onto those steps before a diff is drawn. Syntax inside the diff goes
  through `diff_highlighter`, which paints `Paint::Color` from the five ink
  steps. `SyntaxTheme::from_kit` is chromatic. Do not use it for Pen's diff.
- `StatusEntry.tracked` distinguishes "new" from a tracked file with a 0/0
  count. Untracked is not a zero-line modification.
- Staged files stay in the one Changes list with their counts. There is no
  separate Staged section. Cost: you cannot see staged versus unstaged at a
  glance. The file is still listed until commit.
- Opening a subdirectory of a repo scopes git paths to that directory
  (`Repo.scope_root` / `scope_prefix`). A relative path never reaches a sibling
  outside the opened folder.
- Checkout is not `git checkout -f`. It refuses, before touching disk or the
  index, when there are staged edits, unstaged edits, an untracked file in the
  way, or the branch is already checked out in another worktree.
- Commit refuses a blank message, a missing identity, an empty index, and an
  unresolved merge (any index stage other than 0). It does not skip conflict
  stages and commit a deletion.
- `GitCli` rejects any argument that starts with `-` or `+`, and any
  subcommand other than `fetch`, `push`, `merge`. That includes `--force`,
  `-f`, `--hard`, `--no-ff`, and `+main`.
- Destructive confirms are inline bars, not a dialog stack. Exact prompts:
  "Discard changes to {name}?", "Remove worktree {path}?", "Merge {branch}
  into {current}?". Declining calls nothing.
- `decide_checkout(dirty)` is `KeepBuffer`. The app calls it before checkout,
  discard, worktree remove, and merge, and again when the user confirms,
  because the buffer may have become dirty while the bar was open. Dirty
  includes the open buffer and anything stashed in `unsaved`. Status line:
  "Changed on disk. Your copy is kept."

## Gotchas the code does not advertise

These are why the Phase 2 review (`71464f9`) exists. Repeat them and you ship
data loss.

**gix 0.90**

- "No repo" is `err.downcast_any_ref::<gix::discover::upwards::Error>()`, not
  a string match.
- `Repository` is `Send`, not `Sync`. Re-discover inside `spawn_blocking`.
  Do not hold a `Repo` across an await.
- Default status collapses untracked directories (`UntrackedFiles::Collapsed`).
  Pen sets `UntrackedFiles::Files` and skips directory entries. Without that,
  a new folder cannot be staged and the error looks like a path escape.
- `status()` must keep `Item::TreeIndex` (staged) as well as `IndexWorktree`.
  Dropping `TreeIndex` makes a fully staged tree look clean.
- `Object` implements `Drop`. Move bytes with `detach().data`, not `.data`.
- After editing an index, call `remove_tree()` before `write`. Otherwise the
  tree-cache extension is written stale (gitoxide issue 2421) and a later
  commit can record the wrong tree.
- `open_index()` failure is not "no index". Synthesize an empty index only
  when `index_path()` does not exist. Any other error must propagate. The
  alternative overwrites `.git/index` with one entry.
- `checkout` in `gix_worktree_state` with `overwrite_existing = true` is a
  force checkout. The preflight in `Repo::checkout` is the safety. Do not
  delete it to "make checkout work".
- Line stats on non-UTF-8 return `(0, 0)`. Pen does not count binary diffs.
- The rename/copy arm of status is unreached. Rewrite tracking is off.

**Paths**

- Escape checks match `Project::read`: no absolute path, no `..`, no `.git`
  segment, and a symlink whose target leaves the root is an error even when
  the file does not exist yet. Walk ancestors until one exists, then
  canonicalize. Checking only `parent.exists()` misses
  `symlink_out/missing/file`.
- `add_worktree` and `remove_worktree` resolve relative paths against the
  worktree root, not the process cwd. If `add_worktree` creates a branch and
  then fails, it deletes that branch. Keep that rollback.
- `prepare_remove_worktree` uses `Force::Never`. A dirty or locked linked
  worktree is refused. That is intended.

**UI thread and Rune**

- One `cmd_rx` loop serves open, save, and tree refresh. Fetch/push/merge run
  on a separate task with an in-flight flag, a 60 s timeout, `GIT_EDITOR=:`,
  and `GIT_MERGE_AUTOEDIT=no`. Putting `Command::output().await` back on the
  main loop freezes Save.
- Git triggers coalesce to the **newest** root. A snapshot is applied only
  when `GitSnapshot.root` is the open project. Otherwise a fast folder switch
  paints the previous repo.
- `border_sides` is `[top, right, bottom, left]`. `[0, 0, 1, 0]` is a bottom
  rule, not a right rule.
- `rich()` wraps by default. `single_line()` exists on `text_input`, not on
  `rich()`.
- `TreeItem::changes` paints kit success/danger (green/red). Pen uses
  `TreeItem::badge` plus the faint token.
- `Tree::selected()` returns an iterator, not `Option`.
- File-tree row ids can be compacted folder paths. The file's real relative
  path is `FileNode.data`.
- Do not clear the commit message or the worktree form until the success
  status arrives. A missing identity used to eat the message.
- Do not show remove on the worktree whose path is `project.root`.
- Editor focus must stay off while the palette, Find, commit bar, or worktree
  form is open. `GitPanelState::has_active_input` is that check. `on_ime`
  uses it too. Forgetting it types into the buffer during IME.
- After checkout, discard, or merge, if the open file is gone from the tree,
  close the page. Do not reload it. Reload of a missing file becomes an OS
  error and a later save resurrects the file. A stale diff page is closed
  the same way.
- Headless `--scene` does not start the Tokio worker the same way a real
  launch does. Demo git state for screenshots is filled in `populate_demo_diff`.

**Process**

- Ponytail full was on for this session: smallest complete change, no feature
  the plan did not name. Shortcut comments use `shortcut: <limit>, <when to upgrade>`.
- Inline plan execution used `.superpowers/sdd/` (gitignored). That scratch
  was deleted. Git history is the record. Do not recreate the ledger.
- Do not start Phase 3 by restating Phase 2. Read this file, then
  `plan/2026-11-10-pen-phase-3-lsp.md`.

## What a future agent should build next

Phase 3 is the next plan, and it is independent of git. Constraints that
already bind it:

- New crate `crates/lsp`, package `pen-lsp`. UI thread never awaits a server.
- No server ships with Pen. Missing `lsp.json` means no servers, and the caret
  still moves.
- Diagnostics are faint ink underlines. A `diagnostic` color under 4.5:1 is
  dropped, same rule as `added` / `removed`.
- Go to definition opens a file only through `Project::read`. A location
  outside the root is ignored.
- A crashed server restarts at most once per minute.

Phase 4 is WASM plugins (WIT host, trap must not kill the editor). Phase 5 is
an agent panel. Neither starts until its plan is the task. Do not pull LSP,
plugins, or an agent into a git fix.

Still deliberately absent, even inside git:

- Credential UI. Fetch/push fail closed when the helper cannot run headless.
- `pull`, rebase, reset, force.
- A second Staged section.
- Colored git status.

If you add any of those, it is a new product decision. Ask first.
